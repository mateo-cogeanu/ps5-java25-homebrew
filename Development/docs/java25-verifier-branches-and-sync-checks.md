# Defined verifier decoding and checked native synchronization

A later console run stopped during thread startup, with no captured signal, native termination or fatal report. Its last successfully loaded classes include JOML Matrix4x3f; that is progress evidence, not a proven fault site. The resource sampler stopped earlier than the user's estimated closure time. The earlier compiler-TLS fallback path had no markers in this capture, so this run does not validate or disprove that repair.

Running the actual legacy verifier against Matrix4x3fc/Matrix4x3f with UBSan reproduced a left shift of a negative signed branch byte. Patch 0052 decodes signed branch offsets by multiplication instead, and decodes the high signed word of switch data arithmetically. The resulting signed values and subsequent legal-target checks are preserved. This removes a confirmed C undefined behavior defect; it is not evidence that this defect caused the console crash.

The verifier integration runner now uses UBSan halt_on_error, so a sanitizer finding cannot be followed by a misleading successful exit. The full actual-verifier JNI regression passes for both classes with real mapped allocation, refused libc allocation and exhausted mapping budgets. A separate sanitizer test extracts the actual decoding expressions: it checks every signed16 branch value and signed32/switch boundaries, including negative offsets and INT32_MIN/MAX.

Patch 0053 replaces POSIX synchronization status assertions with a PS5 product-build check. Previously those assertions compiled away in a release VM. The new helper records the actual operation, return status, native identity and errno before taking HotSpot's fatal-error path. Successful calls, valid timed-wait timeouts and trylock-busy results retain their existing behavior; other platforms retain the original assertions. This prevents a failed initialization from silently proceeding to use an invalid native synchronization object. It does not provide an allocation fallback or establish that initialization failed in the captured run.

Child/parent startup handshake checkpoints bracket monitor acquisition, notification and waiting, retaining the same operations and ordering. They help distinguish the last recorded child-entry interval from an actual monitor/condition failure. ASan/UBSan checks compile the actual helper and PlatformEvent constructor with injected condition/mutex initialization ENOMEM, successful initialization and accepted timeout/busy statuses. Target compilation and console validation are separate checks; the new crash cause and actual consumer readiness remain unresolved until console evidence establishes them.
