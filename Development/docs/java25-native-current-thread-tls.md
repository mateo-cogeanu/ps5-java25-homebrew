# PS5 current-thread pointer uses native pthread TLS

Patch 0049 removes `Thread::_thr_current` compiler TLS on PS5. `Thread::current_or_null()` uses the existing guarded library TLS lookup, and initialization/clear set the existing native pthread key once. Other targets keep their compiler TLS. The native POSIX backend, JNI destructor restoration, signal-handler lookup and generated-code JavaThread register contracts are unchanged. Before TLS initialization a lookup returns null.

Evidence: build 022 run 01.000.022-1792167902-443606310 records a successful native create, successful stack-query attribute acquisition and stack recording (base0x7ed778000 size1MiB), then `THREAD: before compiler TLS assignment` without `compiler TLS assigned`. Another thread completes a normal native commit afterward. This narrows the failing child interval; it is not an exact fault PC or proof of an allocator return. Target code for the old `_thr_current` invokes `__emutls_get_address`; emulation may allocate on first per-thread access. The patch eliminates that first-access dependency for HotSpot's current-thread pointer. It does not globally replace every compiler TLS variable or establish that PS5 pthread key operations cannot fail.

Validation: extracted actual Thread lifecycle/getter bodies plus actual POSIX TLS backend under ASan/UBSan, 16 concurrent pthreads, 1600 initialization/clear cycles, signal-time lookups, pre-init null, parent isolation and JNI destructor restoration. Target LLVM IR contains pthread key/get/set calls and no compiler TLS emulation, `_thr_current`, direct allocator or C++ initialization guard. Full target HotSpot build and linked-symbol checks verify the compiler TLS current-pointer symbol is absent. Host tests do not emulate PS5 kernel TLS behavior. All PS5 server lifecycle rows remain pending for build 023.
