# Descriptor-first PS5 canonical paths, development0125

Consumer112 logs confirm repeated chunk-read/write failures with EMFILE. The soft-limit mitigation did not prevent them. The initial fcntl-based scan returned only unknown results, so it did not establish actual handle counts. The leak owner is not proven.

Patch0125 uses the existing checked descriptor canonicalizer first for absolute PS5 paths, avoiding a repeated desktop realpath call that previously returned EPERM before the same walk. Every path component is still opened without following links; missing components, non-directory parents and errors remain failures. There is no lexical existence bypass, cached result or game-class change. Symlinks (ELOOP) and relative paths still request native canonicalization. Other operating systems retain native behavior. This removes an unsupported call from the hot path; it is not evidence that this call leaked handles on PS5.

The actual JNI method passes in a host JVM with ZipFS mounting/reading, canonical dot/parent handling, missing/file-parent/link refusals, native link handling and4096 repeated lookups that never invoke desktop realpath. The walker passes ASan/UBSan and4000 success/error paths under a64-descriptor limit. Cached target java.base-libs rebuilds successfully. Existing clean patch replay still has the documented earlier0009 conflict;0125 reverse-checks against the cached source. PS5 chunk loading, saving and sustained handle usage remain pending.

Descriptor diagnostics now use sceKernelFstat on PS5, decode native error results and distinguish regular files, directories, sockets and unknown probes. Host uses fstat. Existing hard caps are preserved. The optional file_activity.hpp accounts for consumer-linked open/close calls with bounded static storage, no handle ownership and no cleanup of other code's files. Its in-memory /file-activity.txt endpoint works without opening another report. It is a best-effort record, may miss native library internals or racing reuse, and must be compared with native inventory rather than treated as a complete leak detector. It is enabled only when the consumer explicitly instruments its call sites. Frozen runtime snapshots are unchanged.
