# Preinitialized attributes for stack discovery

Patch 0048 extends the PS5 attribute lease backend with a separate stack-query domain. Both domains prime 32 real pthread attribute objects during early initialization. The BSD stack-discovery path borrows a query object and still calls the actual pthread_attr_get_np and stack getters; it does not infer or invent stack bounds. Query objects never enter the creation pool: get_np can set a live stack address, which must not be reused as a new thread stack. Exhaustion retains ordinary local initialization and real error propagation. Objects are borrowed exclusively by pointer, never copied; local objects are destroyed and cached objects retained for process lifetime.

The 021 console trace ends after successful pthread_create and child native entry, before stack recording/current-thread initialization completes. The source still performed a fresh pthread_attr_init during stack recording. Earlier console evidence established ENOMEM from this API under native-heap pressure. This fixes that remaining late allocation but does not prove it caused the 021 termination: no signal, abort, or fatal report was captured. Intermediate stack-query, recorded-stack, compiler-TLS and pthread-TLS checkpoints distinguish subsequent failures.

Validation: actual attribute helper under ASan/UBSan; denied late init, 100 query reuses, isolated stack addresses, both pool exhaustion/local cleanup, early failure/reuse, 800 real pthread creations across concurrent creators. Target LLVM IR checks static/atomic attribute storage without allocator, emulated TLS or C++ initialization guards. Target HotSpot compilation succeeds. Host tests do not emulate the PS5 pthread library or establish console success.
