# Extended attribute capability (0116)

The106 console run emits the ownership EPERM marker and advances to flistxattr during configuration attribute copying, then terminates without a current abort/fatal report. The matching SDK routes the BSD extended-attribute list operation to an unvalidated raw syscall stub. The trace establishes the next boundary, not the exact native termination mechanism.

PS5 now reports extended attributes as unsupported consistently: native SUPPORTS_XATTR is excluded; all four get/set/remove/list JNI operations throw ENOTSUP before native calls; BSD filesystem views omit user on PS5; typed and named provider lookups return no user view; optional BSD extended-attribute copying returns before querying that unsupported capability. Existing callers/stale views still receive a real error from native guards rather than a fake empty list or false write success. Ordinary file data/basic attributes, the existing copy flow and other-platform Java view behavior remain. This does not implement PS5 xattrs or validate neighboring timestamp/permission operations.

Host tests compile the actual BSD filesystem/provider classes and current target user-attribute support classes into a java.base patch module, together with actual JNI capacity/ownership/xattr/canonicalization bodies in a real JVM. Separate desktop and PS5-name processes validate supported-view sets, typed/named lookups, twenty byte-correct COPY_ATTRIBUTES copies, zero extended-attribute calls on the PS5 Java skip path and real ENOTSUP handling on the desktop Java path with injected unsupported native operations. All four direct JNI entries expose exact ENOTSUP; explicit PS5 user writes fail, and a stale available view does not fabricate an empty list. Prior ownership/capacity/canonicalization/data-error controls remain. XcheckJNI/UBSan, target java.base classes/native libraries and exact patch checks pass.

Actual PS5 config-copy continuation, attribute/timestamp behavior, application readiness and persistence remain pending. Frozen passing snapshots are preserved.
