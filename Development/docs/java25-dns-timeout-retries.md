# Bounded DNS timeout retries

The scoped adapter for the pinned SDK netdb.o now makes at most three synchronous attempts when its default lookup returns resolver error226. Build101 reports the native result0x804101E2 and neterrno226 during its first discovery lookup, after successful early pool/resolver preparation. The reported direct-memory policy and kernel failure counters remain zero. Paper is never launched in that run, so it does not validate the increased memory allowance under Paper load.

The adapter retains the same real resolver/pool lease across attempts. It retries only a completed timeout, keeps the SDK's original timeout/retry parameters, and stops immediately on success or a different error. Explicit nondefault timeout/retry/flag calls pass through once using the original output pointer. There are no extra pools, cached/preselected addresses, unverified network routes or authentication/TLS changes. Successful default queries publish only a successful answer and restore entry errno/network errno. Exhaustion exposes the final actual failure through the existing SDK/Java path. An outage can still fail, and three default native calls may take longer than one; this is an attempt bound, not a measured wall-clock guarantee.

Host ASan/UBSan tests compile the actual adapter and SHA-pinned SDK lookup/conversion/cleanup bodies. They cover timeout recovery on attempts2/3, exact three-call exhaustion, timeout followed by permanent error, permanent error without retry, explicit timeout/async-flag passthrough, failed-answer isolation, errno, retained lease recovery,400 cross-thread fresh lookups, late allocation refusal and partial cleanup. PS5 DNS recovery and subsequent Paper startup remain pending.

Sources: [pinned SDK resolver call and EAI conversion](https://github.com/ps5-payload-dev/sdk/blob/v0.42/libc/netdb.c), [public resolver error enum226](https://github.com/vitasdk/vita-headers/blob/master/include/psp2/net/net.h). The latter is the related public SDK enum; the actual PS5 numeric failure is captured in local reports, not inferred from the enum alone.

Console observation: consumer102 executes all three native query attempts with error226 and emits retry2/3 diagnostics, then releases the lease and propagates the failure. Recovery is not established. The configured resolver's DNS service was unreachable during investigation, while its host answered ping; distinguish network/service availability from allocator failure. Device addresses and raw logs remain local. No further runtime change is justified by this result alone.
