## Directory stream backend

Patch0062 replaces PS5 JNI opendir/readdir/closedir with a private descriptor-backed handle. Resident open verifies a directory with O_DIRECTORY and follows normal directory symlinks as the original opendir contract does. A mapped fixed-size buffer avoids allocating a fresh libc DIR under pressure. Enumeration calls the actual libkernel sceKernelGetdents export, not an SDK raw syscall. The pinned FreeBSD directory wire format has a32-bit inode,16-bit record length,8-bit type/name length and name bytes at offset8. Record boundaries, terminator and embedded NULs are checked before copying a name. Oversized/truncated/malformed data becomes sticky EIO, encoded SCE errors become errno and EOF remains distinct. EINTR retries; close releases the descriptor and mapping. Optional SecureDirectoryStream remains unavailable rather than claiming anchored operations.

The SDK stub exports sceKernelGetdents; [PS5Dev's direct usage](https://github.com/PS5Dev/Byepervisor/blob/main/src/self.cpp) corroborates its declaration and directory-record format. This implementation uses bounded parsing rather than relying on a sentinel beyond the returned byte count.

`python3 tools/test_java25_directory.py` registers the actual three JNI bodies in the host JVM and clears its optional openat capability to exercise the PS5 directory path. A test-only adapter serializes real host directory entries to the pinned wire format. Real Files.walk and directory iteration cover Unicode, symlink following, missing/non-directory errors and repeated cleanup. Separate actual-helper ASan/UBSan tests inject malformed/oversized/truncated/embedded-NUL records, encoded errors, EINTR, EOF and sticky failure behavior. Host serialization is not target kernel validation.

## Genuine operation checks after access EPERM

ZipFS explicitly requires provider.checkAccess(READ) before opening its channel. Patch0063 retains native access success and all non-EPERM errors. For EPERM only, F_OK/READ/WRITE checks can be satisfied by an actual non-creating, non-truncating descriptor open with the requested read/write mode, followed by fstat of a regular file or directory and close. Missing paths and actual open/fstat/close failures remain failures. EXECUTE/search permissions are never inferred from readable contents. Devices/FIFOs are not treated as verified access. This checks actual effective process operations and is conservative where real-identity access semantics differ; it is not a general ACL or directory-write authorization oracle.

`python3 tools/test_java25_access.py` registers the actual JNI access0, injects native EPERM and mounts/reads a real ZipFS. It tests combined read/write, no execute inference, missing paths, unchanged contents, repeated calls and unchanged EACCES/native-success behavior. The build036 verification error is consistent with the access query, but its complete throw stack was not retained. Build037 preflight separates checkAccess, directory enumeration and mount; native access entry/result checkpoints narrow any remaining failure.

Target java.base-libs rebuild and host tests pass; real PS5 directory enumeration, access/ZipFS and server ready/save/stop remain pending. No official world validator or game JAR is modified by these repairs.

Patch0064 tries resident sceKernelGetdirentries only when initial sceKernelGetdents returns EINVAL/ENOSYS, before any record has been delivered, and only after a successful rewind. Once delivery starts there is no alternate/replay, preventing duplicate enumeration. Both entry points retain bounded parsing, encoded-error handling and real failure propagation. The same patch adds a shared native stream/zlib allocator for PS5 Inflater and Deflater. Realloc is not involved. Both allocation backends failing still produces the original native OOM. Other platforms retain their existing allocator paths and zlib checks. No heap increase, archive-integrity bypass or changed game code is involved.
