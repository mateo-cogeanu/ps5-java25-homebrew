# Checked native TLS updates and bounded failure fallback

Patch 0050 checks the actual `pthread_setspecific` return and immediate native readback on PS5. Ordinary successful updates/reads continue using the existing pthread key. A refusal or readback mismatch stores the real current Thread pointer in a static atomic table keyed by `pthread_self`; reads prefer that override. A refused clear stores an explicit null override, preventing a stale native key from exposing a detached Thread. A subsequent successful update removes the override. The JNI key destructor respects a null override so it cannot resurrect a detached/deleted Thread after a refused clear; otherwise it preserves restoration semantics.

The table allocates no memory, uses no compiler TLS and retains up to 1024 distinct fallback thread identities per process, including inactive identities. Reused identities reuse their slot. Exhaustion reports a fatal failure instead of silently continuing with the wrong current pointer. Native JNI callers must still detach before exiting. Native key creation failure is now fatal in product builds too. This does not pretend the underlying OS key operation succeeded.

Build 023 advanced beyond TLS assignment, handshake and Java thread entry. Its fatal report records SIGSEGV, current thread native, approximately 25 MiB metaspace and 26 collections. The captured register values are inconsistent (including SP0x388 and error-report PCs inside a recorded stack); no exact fault location or native-key refusal was captured. The ignored product-build setter failure is a concrete error-handling gap, not a proven explanation of this console crash. New diagnostics record setter result/readback and raw first256 bytes of the supplied signal context without changing any ABI offsets. The last completed malloc record is not the fault site or allocation result.

Validation: actual lifecycle/getter bodies and POSIX backend, real host pthread keys with injected failures, ASan/UBSan; 8000 concurrent initialization/clear cycles covering nonnull refusal, all-update refusal, stale clear, false-success readback, recovery and signal-time lookup. Tests model POSIX destructor entry and verify refused clear cannot resurrect a Thread. Separate helper test covers 1024 colliding identities, exhaustion, explicit null, reactivation and errno. Target IR has native key calls and static atomics without direct allocators, compiler TLS emulation or lazy C++ guards. Actual raw formatter tests cover misalignment, short bounds, maximum256-byte cap, null, errno and partial/EINTR writes. Target build/package and PS5 results are recorded separately; host checks do not establish console crash resolution.
